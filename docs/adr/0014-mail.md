# 0014. Mail: address as identity, mailboxes via external providers

- **Status:** Accepted
- **Date:** 2026-11-03

## Context

Companies expect `name@company.com` to exist automatically for new hires and to be used across all services. Running mail servers is hard (deliverability, storage, reliability) and a top source of anxiety for self-hosters.

## Decision

- **Address as identity (v0.1):** each person gets `username@company-domain`. It is used for sign-in, Git commits and service accounts, and no mail server is required for this.
- **Mailboxes are the `mail` capability with external providers** (candidates: Purelymail, Migadu, Google Workspace, Microsoft 365, to be researched). Orglane creates mailboxes on hire and removes them on offboarding through provider APIs. Forwarding-only setups are supported for very small teams.
- **System email** (invites, notifications) uses configured SMTP or a transactional service, separate from employee mailboxes.
- The setup wizard checks DNS records (SPF, DKIM, DMARC).
- A self-hosted mail server option (for example Stalwart, with an outbound relay) may come much later, with clear warnings.

## Consequences

- The "hire → address and mailbox everywhere" experience without operating SMTP.
- Mailbox provisioning ships in v0.2 at the earliest (optional scope).
